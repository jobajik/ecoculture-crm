## 1. Грабли — прочитать до первой правки

**1.1. Колонка `Farm` во вкладке Users обязана быть ПОСЛЕДНЕЙ.**
Данные из таблицы читаются **по позиции**, а не по названию колонки: `rowToRecord()` берёт список
заголовков из `SHEET_HEADERS` в `src/lib/constants.ts` и раскладывает ячейки строки по порядку.
Заголовки в самой Google-таблице при чтении не используются вообще.

Если вставить `Farm` в середину — все колонки правее сдвинутся. Это уже случалось: `Farm`
оказалась четвёртой, и программа читала производство из колонки `Active` (получала `"true"`), а
активность — из колонки `Farm`. Итог: зав. складом заходила в систему нормально, но склад у неё был
пустой, потому что производства с названием `true` не существует и фильтр отсекал всё.

Любую новую колонку добавлять **только в конец** — тогда существующие строки не поедут.

**1.2. Сервисный аккаунт Google не используется — только refresh-токен.**
Организационная политика Google блокирует создание ключей сервисных аккаунтов
(`iam.disableServiceAccountKeyCreation`), и обойти её владелец не может. Поэтому доступ к таблице
идёт через `GOOGLE_OAUTH_REFRESH_TOKEN`. Переменные `GOOGLE_SERVICE_ACCOUNT_*` в коде поддержаны
(`buildAuth()` в `src/lib/sheets.ts` умеет оба способа), но пустые. Не пытаться «починить» через
сервисный аккаунт — это тупик.

**1.3. Приложение Google в режиме тестирования.**
Каждого нового сотрудника нужно вручную добавить в Google Cloud → APIs & Services → Аудитория →
Тестовые пользователи. Без этого при первом входе он получит `403 access_denied` — и это выглядит
как поломка CRM, хотя дело в Google.

**1.4. Шрифт подключается через `@fontsource/arimo`, а не `next/font/google`.**
Сборочное окружение не имеет доступа к Google Fonts, `next/font/google` падает. Шрифт Arimo
самохостится пакетом.

**1.5. Печатный лист сборки настроен под одну страницу A4 — не трогать числа наугад.**
`src/components/PicklistView.tsx`: `PAGE_WIDTH = 1052` (печатная ширина ландшафтной A4 при полях
8 мм — примерно 1062 px, 1052 с запасом), `PAGE_HEIGHT = 724`. Масштаб `--print-scale` считается в
JS по фактической высоте документа. В `globals.css` блок `@media print` задаёт
`.doc-frame { height: 194mm; overflow: hidden; margin: 0 }` — `margin: 0` здесь обязателен, иначе
отступ от `space-y-*` создаёт пустую вторую страницу.

Проверялось генерацией PDF на наборах 3×5, 8×17, 12×25, 16×34, 20×40 (клиентов × позиций) — везде
одна страница.

**1.6. Проверяйте доставку файлов обратным чтением.**
Отправка файла на компьютер владельца может отчитаться «записано», а на диске останется старая
версия. Так уже терялось важное исправление. После записи — считать файл обратно и убедиться, что
содержимое то самое.

## 3. Предметная область

**Два производства (ТОО).** Это сквозная идея, она задевает почти всё:

| Код | Производство | Что выращивает |
|---|---|---|
| `rose_farm` | Rose Farm | розы, эустома |
| `esentai` | Есентай Агро Хим | хризантема |

У каждого свой зав. складом. Он видит остатки, принимает партии, отгружает, списывает и печатает
лист сборки **только по своему цветку**. Менеджеры и админ работают по обоим. Заявка менеджера может
содержать любой цветок — на печати она автоматически делится между двумя складами.

Связь «тип цветка → производство» задана в `FARM_BY_FLOWER_TYPE`. Всё остальное считается от неё:
`getFarmFor()`, `flowerTypesForFarm()`, фильтры `farmFilter` в `getStockSnapshot()`,
`getPicklist()`, разбивки `byFarm` в аналитике.

**Роли:** `admin` (всё + Настройки), `manager` (заявки, продажи), `warehouse` (склад своего
производства). Роль и производство берутся из вкладки `Users` при каждом обновлении токена — менять
права можно на ходу, перезапуск не нужен.

**Градации** (`GRADES_BY_FLOWER_TYPE`):
- роза — 40/50/60/70/80/90/100 см, Мини-микс, Уценка, B-quality
- хризантема — Высшая, Первая, Вторая, Третья, Четвёртая, Мини-микс, Уценка
- эустома — Стандарт, 50, Мини-микс, Уценка

**Сорта** ведутся на вкладке `Varieties`; значения по умолчанию — `DEFAULT_VARIETIES`.

**Сроки хранения** (вкладка `Settings`): роза 7 дней, хризантема 18, эустома 10, порог
предупреждения 70 % от срока. Статусы: `ok` → `warning` → `critical`.

**Списание со склада — FIFO** по дате срезки (`harvestDate`), не по дате приёмки.

```

    page.tsx                 главная: живые остатки (StockBoard)
    orders/                  заявки: список, создание, детали
    warehouse/
      actions.ts             серверные действия склада + проверка производства

      receive, batches, ship
    sales/, sales/day/       продажи менеджеров, дневной дашборд
    analytics/               цены, списания, сроки
    admin/                   сотрудники, производства, сроки хранения
    api/                     stock, sales, sales/day, warehouse/picklist, warehouse/template
  lib/
    constants.ts             ★ схема таблицы, производства, градации, сорта
    sheets.ts                доступ к Google Sheets (два способа авторизации)
    repo/                    чтение/запись по вкладкам
    stock.ts                 остатки + сроки хранения (farmFilter)
    picklist.ts              сводная заявка на день (farmFilter)
    salesAnalytics.ts        месяц: план против факта, byFarm
    dailySales.ts            день: кто сколько продал, byFarm
    excel.ts                 импорт приёмки, шаблон, выгрузка листа сборки
  components/                StockBoard, PicklistView, формы, дашборды
```

`src/lib/constants.ts` — главный файл. Почти любое изменение предметной области (новый сорт,
градация, тип цветка, производство) начинается там.

**Правило разграничения по производству:** любое действие склада проходит через
`assertOwnFlowerType()` в `src/app/warehouse/actions.ts`. Это серверная проверка, а не пряталки в
интерфейсе — подделать запрос не выйдет.

## 5. Как вносить правки

Правки идут через компьютер владельца — прямого доступа к его GitHub у Claude нет и не должно быть
(токены остаются у владельца).

```
правка кода → запись в папку на компьютере → sync.bat → GitHub → Vercel собирает сам → сайт
```

Папка проекта: `C:\Users\StarlineComp\Downloads\flower-crm_1\flower-crm`

**Компьютер должен быть включён и с запущенным приложением Claude.** Владельцу при этом не нужно
быть за ним — команды он даёт хоть с телефона.

**Приём для выполнения команд на компьютере.** Печатать в терминал нельзя (ограничение доступа), но
можно положить в папку `.bat`-файл, запустить его двойным кликом через Проводник и прочитать
результат из файла, куда скрипт пишет вывод. Так ставились Git, GitHub CLI и Vercel CLI.

**Полезные скрипты в папке** (в репозиторий не попадают):
- `start-crm.bat` — локальный запуск на `localhost:3000`
- `sync.bat` — отправить изменения на GitHub (дальше Vercel сам)

**Команды проекта:** `npm run dev`, `build`, `lint`, `setup-sheet` (создаёт/обновляет вкладки),
`get-refresh-token` (получить refresh-токен заново).

**Переменные окружения** — в `.env.local` локально и в Vercel для боевого:
`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL`,
`GOOGLE_SHEETS_SPREADSHEET_ID`, `GOOGLE_OAUTH_REFRESH_TOKEN`.
`.env.local` в репозиторий не коммитится никогда.

**Новый домен** требует двух правок в Google Cloud → Credentials → Web client 1: добавить домен в
Authorized JavaScript origins и `<домен>/api/auth/callback/google` в Authorized redirect URIs.

## 6. Логика, которая неочевидна

**Лист сборки** (`picklist.ts`) собирается **по дате доставки**, а не по дате заявки, и открывается
на сегодня. Отгруженные (`shipped`) и отменённые заявки в него не попадают намеренно: лист отвечает
на вопрос «что сегодня набрать из холодильника», а по отгруженной заявке набирать нечего. Пустой
лист чаще всего означает не поломку, а отсутствие доставок на выбранную дату.

**Продажи менеджера** считаются по дате оформления заявки, а не отгрузки.

**Средний возраст склада** — взвешенный по количеству стеблей, не простое среднее по партиям.

**Импорт приёмки из Excel** сверяет сорт со справочником `Varieties` и отклоняет неизвестные.
Строки чужого производства помечаются ошибкой. Шаблон скачивается уже под своё производство.
